👥 User Management Flow
Admin-only operations — all routes require 🛡️ Admin Role

User CRUD + Role Assignment

🔒 Security Guards

All endpoints enforce:

🔑 Authenticated session 🛡️ Admin role required ⚠️ Cannot self-deactivate ⚠️ Cannot remove own admin

📊 Role Level Logic

When assigning a role, the legacy role field is auto-updated:


level >= 100 → role = "admin"

level < 100 → role = "user"


Primary role = assignment with highest level number

🔄 User Types

Local Admin — has localUsername + bcrypt password. Created via CLI script.


PWA User — has pwaUsername. Auto-created on first login from external API, profile synced each login.

🏷️ Role Management Flow
CRUD operations on roles + toggle active state. All routes require admin authentication.

Role CRUD Operations

🏷️ Role Data Model

name — Unique identifier (e.g. "admin", "manager")


level — Numeric hierarchy. Level ≥ 100 grants admin privileges. Used to determine primary role.


permissions[] — Text array of permission strings (e.g. ["users:read", "roles:write"])


isActive — Inactive roles cannot be assigned to users

⚙️ Business Rules

• Role name must be globally unique


• Deleting a role cascades — all user_roles assignments for that role are also removed


• Inactive roles (isActive = false) are blocked from new assignments in the PUT /users/[id]/roles endpoint


• The "admin" role in users.role is inferred from role level, not directly set on role operations

📡 API Reference
All endpoints follow { success: true, data: {...} } / { success: false, error: "...", code: "..." } pattern
Method Endpoint Auth Request Body Description & Notes
Authentication
POST /api/auth/login Public { username, password } Dual strategy: local (bcrypt) → PWA (external API). Returns { isLoggedIn, firstname, role } + sets HTTP-only cookie
POST /api/auth/logout Any — Destroys session, clears cookie. Redirects to /login
GET /api/user Logged in — Returns current session user data
User Management (Admin only)
GET /api/admin/users Admin — List all users with assigned roles. Primary role = highest level. Ordered by firstname, lastname.
PUT /api/admin/users/[id] Admin { role: "admin"|"user" } Update legacy role field directly. Guard: cannot remove own admin role.
PUT /api/admin/users/[id]/active Admin { isActive: boolean } Activate or deactivate user account. Guard: cannot deactivate own account.
GET /api/admin/users/[id]/roles Admin — Get all role assignments for a specific user with metadata
PUT /api/admin/users/[id]/roles Admin { roleId: UUID } Replace all role assignments. Removes existing, assigns new. Updates legacy role field based on level ≥ 100. Role must be active.
Role Management (Admin only)
GET /api/admin/roles Admin — List all roles
POST /api/admin/roles Admin { name, description?, level, permissions[] } Create new role. Name must be unique. Returns 201 on success.
PUT /api/admin/roles/[id] Admin { name?, description?, level?, permissions?, isActive? } Partial update of any role field
DELETE /api/admin/roles/[id] Admin — Delete role. Cascades to remove all user_roles assignments for this role.
PUT /api/admin/roles/[id]/toggle-active Admin — Toggle role's isActive status. Inactive roles cannot be assigned to users.

200OK — success
201Created — new role created
400Bad Request — validation error, self-guard
401Unauthorized — no session / bad credentials
403Forbidden — not admin role
404Not Found — user or role not found
500Internal Server Error — unexpected
