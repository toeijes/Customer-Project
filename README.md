# ระบบติดตามและประเมินโครงการวางท่อขยายเขตจำหน่ายน้ำประปา กปภ.ข.6 (PWA Area 6 Expansion System)

ระบบแดชบอร์ดติดตาม ประเมินความคุ้มทุน และวิเคราะห์พิกัดแผนที่ผู้ใช้น้ำของโครงการวางท่อขยายเขตจำหน่ายน้ำ ในพื้นที่ความรับผิดชอบของ กปภ.เขต 6 (ภาคตะวันออกเฉียงเหนือ) ครอบคลุม 8 สาขาเป้าหมายยุทธศาสตร์ ดึงข้อมูลพิกัดและยอดติดตั้งมิเตอร์ใช้น้ำประปาโดยตรงประสานร่วมกับระบบ PCIS

---

## 🛠️ เทคโนโลยีที่ใช้งาน (Technology Stack)

*   **Frontend**: React 19 (Vite), TailwindCSS v4, Leaflet Map (แผนที่ระบบภูมิสารสนเทศ), Recharts (กราฟสรุปสถิติ), Lucide React (ชุดไอคอน)
*   **Backend**: Node.js, Express API Server (CommonJS)
*   **Database**: MySQL Server 8.4 (พอร์ต `3306` ฐานข้อมูลเริ่มต้น `pwa6_expansion` หรือปรับแต่งผ่าน `backend/.env`)
    *   ระบบเชื่อมต่อข้อมูลใช้ชุดรหัสอักขระภาษาไทยและเปรียบเทียบแบบ UTF-8 (`utf8mb4_unicode_ci`) สมบูรณ์ เพื่อหลีกเลี่ยงข้อผิดพลาด Collation Mismatch
    *   รองรับการประเมินจากคอลัมน์สมัครใช้น้ำแบบ `BGN_DATE` (ตาราง `customer`) โดยแปลงปี ค.ศ. เป็น พ.ศ. อัตโนมัติ และระบบวันที่สำรอง `bgncustdt` (ตาราง `proj_cus`)

## 💡 ฟีเจอร์การทำงานของระบบ (Key Features)

1.  **รายงานข้อมูลรายโครงการ & แผนที่ระบบภูมิสารสนเทศ (Overview & Interactive Map)**
    *   การ์ดสรุป KPI (จำนวนโครงการ, วงเงินงบประมาณรวม, เป้าหมายผู้ใช้สะสม และผู้ใช้น้ำจริง)
    *   แผนที่รวมหมุดเฉลี่ยโครงการ และแผนที่แสดงพิกัดผู้ใช้น้ำจริง (สีเขียวเทอร์ควอยซ์) สามารถคลิกรายชื่อเพื่อเคลื่อนแผนที่ไปยังพิกัดลูกค้า (Pan)
    *   ตารางรายละเอียดโครงการ ค้นหา คัดกรอง ค้นรหัส หรือส่งออกเป็น CSV
    *   **การแสดงเลขที่สัญญา (Contract Number):** แสดงเลขที่สัญญา (เลขที่สัญญา/วันก่อสร้างแล้วเสร็จ) บนการ์ดข้อมูลและหัวข้อป๊อปอัพรายชื่อผู้ใช้น้ำ เพื่อให้พนักงานและผู้ดูแลระบบสามารถตรวจสอบเอกสารอ้างอิงได้อย่างชัดเจน
*   **ปุ่มแก้ไขสัญญา (Planning & Admin เท่านั้น):** สามารถแก้ไขเลขที่สัญญาและวันก่อสร้างแล้วเสร็จได้ทันทีจากหน้าระบบ โดยเลขที่สัญญาสามารถเว้นว่างเพื่อกรอกภายหลังได้ ระบบจะลบช่องว่างทั้งหมดก่อนบันทึกและปฏิเสธเลขที่สัญญาที่มีโครงการอื่นใช้อยู่แล้ว
2.  **วิเคราะห์ยอดรายเดือนรายสาขา (Monthly Performance Matrix)**
    *   ตาราง Matrix Grid สรุปยอดผู้ใช้รายเดือนและสาขา พร้อม Heatmap แสดงความหนาแน่นเชิงผลสัมฤทธิ์
    *   ระบบเจาะลึกข้อมูล (Drill-down) คลิกที่ช่องตัวเลขเพื่อแสดงรายชื่อลูกค้าจริงในเดือนนั้นๆ (พร้อมแสดงเลขที่สัญญาประกอบในรายการย่อย)
    *   ปรับมุมมองอัตโนมัติตามสิทธิ์ (ซ่อนแถวผลรวมระดับเขต กปภ.ข. สำหรับสิทธิ์ที่ต่ำกว่า RegAdmin เพื่อความกระชับ)
    *   มีปุ่ม Export ข้อมูลตารางเป็นไฟล์ CSV ได้ทันทีในรูปแบบที่อ่านง่าย
3.  **ประเมินจำนวนผู้ใช้น้ำตามเป้าหมายโครงการ (Break-even Analysis)**
    *   แสดงเป้าหมายสะสม (Cumulative Target) เทียบกับผลงานสะสมที่เกิดขึ้นจริง (Cumulative Actual) เป็นกราฟเส้น
    *   เรียงลำดับโครงการใน Dropdown อ้างอิงตามอัตราความสำเร็จสูงสุดลงไปต่ำสุด พร้อมจุดสีบอกระดับความสำเร็จ (🟢 เขียว $\ge 100\%$, 🟡 ส้ม $\ge 70\%$, 🔴 แดง $< 70\%$)
4.  **วิเคราะห์ปริมาณการใช้น้ำสะสมและค่าน้ำสะสม (Water Consumption Analysis)**
    *   วิเคราะห์ประวัติการเปิดมิเตอร์ใช้น้ำ ค่าน้ำสะสม (บาท) และปริมาณการใช้น้ำรวม (ลบ.ม.)
    *   วิเคราะห์และเจาะลึกประวัติใช้น้ำรายบิลรายเดือนย้อนหลัง 12 เดือน (M0 ถึง M12) ของผู้ใช้น้ำแต่ละรายในโครงการ เพื่อตรวจสอบมาตรชำรุด หรือลูกค้าย้ายออก
    *   แสดงผลรวดเร็วทันใจในระดับมิลลิวินาที ด้วยสถาปัตยกรรมตารางสรุป (Materialized View / Summary Tables) ที่คำนวณเบื้องหลังผ่านสคริปต์ `update_data.js`
5.  **แผงควบคุมระบบการจัดการสิทธิ์ (Admin Console)**
    *   แผงจัดการผู้ใช้งาน (การระงับบัญชี/เปิดใช้งาน)
    *   การกำหนด Role ระดับสิทธิ์ผ่านเมนูดรอปดาวน์
    *   **การนำเข้าและลบข้อมูลโครงการด้วยไฟล์ CSV (Bulk CSV Import):** สงวนสิทธิ์เฉพาะ Admin และ RegAdmin เท่านั้น (โดย RegAdmin สามารถจัดการได้เฉพาะในเขตของตน) ข้อมูลถูกบันทึกลงตาราง `projects` และ `plan_master` ภายใต้ Database Transaction พร้อมสั่งคำนวณ KPI ใหม่
    *   **ตารางประวัติการนำเข้าไฟล์ (Import History):** บันทึกประวัติการอัปโหลดไฟล์ พร้อมบอกชื่อไฟล์ เวลา ผู้ทำรายการ และผลการนำเข้า
    *   **ประวัติการทำธุรกรรมระบบ (System Audit Logs):** แสดงบันทึกความปลอดภัย พร้อม Tooltip แสดงรายละเอียดตำแหน่ง/สังกัด เมื่อนำเมาส์ไปชี้ที่ชื่อผู้ทำรายการ
6.  **ระบบแสดง/ซ่อนรหัสผ่านในหน้าเข้าสู่ระบบ (Password Visibility Toggle)**
    *   เพิ่มปุ่มดวงตา (Eye / EyeOff) บนช่องป้อนรหัสผ่านก่อนเข้าระบบ เพื่อช่วยให้ผู้ใช้ตรวจสอบความถูกต้องของรหัสผ่านที่ป้อนเข้าไปว่าถูกต้องตามต้องการหรือไม่ ป้องกันปัญหากรอกรหัสผ่านผิดพลาด
    
7.  **ระบบตัวกรองแบบฉลาด (Smart Filters)**
    *   ระบบการเลือกสาขาจะถูก Disable อัตโนมัติ หากผู้ใช้เลือก "ทุกเขต" (All Zones) เพื่อป้องกันการฟิลเตอร์ที่ขัดแย้งกัน ใช้งานได้ครอบคลุมทุกหน้า Dashboards

## 🔑 การแบ่งแยกสิทธิ์ผู้ใช้งาน (Access Roles & Security System)

ระบบแบ่งระดับสิทธิ์การดำเนินงานออกเป็น **3 ระดับ** เพื่อควบคุมขอบเขตความมั่นคงปลอดภัย:

| ระดับสิทธิ์ | ค่าสำคัญ (Level) | ขอบเขตหน้าที่และความปลอดภัย |
| :--- | :---: | :--- |
| **ผู้ดูแลระบบ (Admin)** | **$\ge$ 100** | สิทธิ์สูงสุดในระบบ ทำรายการได้ทุกอย่าง เข้าใช้งานหน้า **Admin Console** สลับสิทธิ์ผู้ใช้ ระงับบัญชี ดู Audit logs และปรับปรุงฐานข้อมูลได้ |
| **เจ้าหน้าที่แผนงาน (Planning)** | **50 - 99** | สิทธิ์ด้านข้อมูลแผนงาน สามารถเพิ่มโครงการใหม่ แก้ไขเลขที่สัญญา และวันที่เสร็จสิ้นโครงการได้ (มีสิทธิ์เขียนข้อมูลผ่าน `requireWriteAuth` Guard) แต่ไม่สามารถเข้าเมนูจัดการแอดมินได้ |
| **ผู้ใช้งานทั่วไป (User/Viewer)** | **0 - 49** | สิทธิ์เริ่มต้นของบัญชีลงทะเบียนใหม่ สามารถเข้าชมและสืบค้นข้อมูลใน Dashboard ทุกแถบได้แบบอ่านอย่างเดียว (Read-only) ไม่สามารถเพิ่ม/แก้ไขข้อมูลใดๆ ได้ |

## 📈 เกณฑ์การประเมินผลโครงการอย่างละเอียด (Detailed Evaluation Logic)

### 1. เกณฑ์ตามประเภทโครงการ
*   **โครงการประเภท 1, 2, 3 (งบปกติ / เงินลงทุน / อุดหนุน / กระตุ้นเศรษฐกิจ):** ประเมินผลสะสม **5 ปี** นับจากปีที่แล้วเสร็จ
*   **โครงการประเภท 4 (วางท่อเข้าซอย):** ประเมินผลระยะสั้น **1 ปี** (เป้าหมาย 100% ในปีที่แล้วเสร็จโครงการ)

### 2. สัดส่วนเป้าหมายสะสม 5 ปี
*   **ปีที่ 1 (Year 1)**: เป้าหมายสะสม **40%** (รวมผลงาน Year 0 และ Year 1 เข้าด้วยกันเพื่อความยุติธรรมด้านเวลา)
*   **ปีที่ 2 (Year 2)**: สะสมเพิ่มอีก 15% (รวมเป็น **55%**)
*   **ปีที่ 3 (Year 3)**: สะสมเพิ่มอีก 15% (รวมเป็น **70%**)
*   **ปีที่ 4 (Year 4)**: สะสมเพิ่มอีก 15% (รวมเป็น **85%**)
*   **ปีที่ 5 (Year 5)**: สะสมเพิ่มอีก 15% (รวมเป็น **100%**)

### 3. เกณฑ์การกรองและนับผู้ใช้น้ำประปา

## 📊 ตารางฐานข้อมูลที่ได้รับผลกระทบจากการจัดการโครงการ (Project Modification Database Impact)

ในการเพิ่ม แก้ไข หรือลบข้อมูลโครงการผ่านทางระบบ (หน้าจอ Admin Console หรือการทำงานผ่าน API) จะส่งผลต่อตารางต่าง ๆ ในฐานข้อมูลดังนี้:

### 1. การเพิ่มโครงการใหม่ (Add Project)
*   **ตารางที่บันทึกข้อมูลทันที**:
    *   `projects`: บันทึกข้อมูลรหัสโครงการ เลขสัญญา ชื่อโครงการ ประเภทโครงการ วันก่อสร้างแล้วเสร็จ งบประมาณ และเป้าหมายผู้ใช้น้ำ
    *   `plan_master`: บันทึกข้อมูลรหัสโครงการและรายละเอียดเบื้องต้น เพื่อรักษาความเข้ากันได้กับชุดโครงสร้างข้อมูลดิบ
    *   `system_logs`: บันทึกประวัติการทำรายการ (Action `CREATE_PROJECT` หรือ `IMPORT_CSV` พร้อมระบุข้อมูล IP และผู้ใช้งานที่ทำรายการ)
*   **ตารางที่ได้รับผลกระทบเมื่อรันสคริปต์คำนวณ (`update_data.js`)**:
    *   `eligible_customers`: ประมวลผลและจับคู่รายชื่อผู้ใช้น้ำที่มีสิทธิ์ของโครงการใหม่นี้
    *   `project_yearly_performance`: คำนวณเป้าหมายและผลงานการติดตั้งมิเตอร์รายปีงบประมาณ
    *   `monthly_actual_users`: บันทึกสถิติความคืบหน้าการใช้น้ำจริงรายเดือน

### 2. การแก้ไขข้อมูลโครงการ (Edit Project)
*   **ตารางที่บันทึกข้อมูลทันที**:
    *   `projects`: อัปเดตข้อมูลที่เปลี่ยนแปลง เช่น เลขสัญญา (`contract_no`), วันแล้วเสร็จ (`completed_date`), ปีงบประมาณที่แล้วเสร็จ (`completion_year`), หรือพิกัดเฉลี่ยโครงการ (`latitude`, `longitude`)
    *   `system_logs`: บันทึกประวัติการกระทำ (Action `UPDATE_CONTRACT` หรือ `UPDATE_COORDINATES`)
*   **ตารางที่ได้รับผลกระทบเมื่อรันสคริปต์คำนวณ (`update_data.js`)**:
    *   หากแก้ **"วันก่อสร้างแล้วเสร็จ (Completed Date)"** หรือ **"ปีงบประมาณที่แล้วเสร็จ"** เกณฑ์กรองประเมินเวลาจะเปลี่ยนไป ส่งผลให้ตารางสรุปข้อมูลคำนวณผลลัพธ์ใหม่ตามช่วงเวลาล่าสุด:
        *   `eligible_customers` (รายชื่อและจำนวนผู้ใช้จะคำนวณใหม่ตามวันติดตั้งจริงหลังวันแล้วเสร็จ)
        *   `project_yearly_performance` และ `monthly_actual_users` (ยอดสะสมรายปีและยอดรายเดือนจะถูกสรุปยอดใหม่ทั้งหมด)

### 3. การลบโครงการ (Delete Project)
*   **ตารางที่มีการลบข้อมูลออกทันที (สิทธิ์เฉพาะ Admin เท่านั้น)**:
    *   เมื่อยืนยันลบโครงการ ระบบจะลบข้อมูลออกตามความสัมพันธ์ของข้อมูลทันที (Cascading Delete):
        1.  `projects`: ลบข้อมูลแถวโครงการนั้นออก
        2.  `plan_master`: ลบข้อมูลแถวโครงการดิบออก
        3.  `eligible_customers`: ลบรายชื่อผู้ใช้น้ำที่ผูกกับโครงการนี้ออกทั้งหมด
        4.  `project_yearly_performance`: ลบสถิติตัวชี้วัดรายปีของโครงการนี้ออกทั้งหมด
        5.  `monthly_actual_users`: ลบข้อมูลผลงานรายเดือนของโครงการนี้ออกทั้งหมด
    *   **ตารางที่บันทึกข้อมูล**:
        *   `system_logs`: บันทึกประวัติการลบ (Action `DELETE_PROJECT` ระบุชื่อโครงการ รหัสโครงการ และชื่อแอดมินผู้ทำรายการ)

## ⏰ การตั้งค่ารันอัตโนมัติประจำวันบนเครื่อง Server (Daily Automated Update)

เครื่อง production จะล้างข้อมูลด้วย `TRUNCATE/DELETE` แล้วนำเข้าข้อมูลดิบชุดใหม่ในตาราง `customer`, `debt_trn` และ `proj_cus` ทุกวัน จากนั้นจึงรันคำนวณสถิติตัวชี้วัดเวลา **02:00 น.** โครงสร้างตาราง generated columns และ indexes จะยังคงอยู่หลังการล้างข้อมูลแบบนี้

1.  **ดึงอัปเดตและตั้งค่าสิทธิ์สั่งรันบน Server**:
    ```bash
    cd /opt/Customer-Project
    git pull
    chmod +x backend/cron_update_metrics.sh
    ```
2.  **รัน schema migration ครั้งแรกหลัง deploy โค้ดชุดนี้**:
    ```bash
    docker compose exec -T backend npm run migrate:performance-indexes
    docker compose exec -T backend npm run verify:performance-indexes
    ```
    Generated columns ใน `proj_cus` ถูกกำหนดเป็น `INVISIBLE` จึงไม่เพิ่มจำนวนคอลัมน์ในคำสั่ง `INSERT INTO proj_cus VALUES (...)` เดิม
3.  **เปิดการตั้งค่า Crontab**:
    ```bash
    crontab -e
    ```
4.  **เพิ่มบรรทัดตั้งเวลาไว้บรรทัดล่างสุด**:
    ```text
    0 2 * * * /bin/bash /opt/Customer-Project/backend/cron_update_metrics.sh >> /opt/Customer-Project/backend/cron_update.log 2>&1
    ```
5.  บันทึกและปิดโปรแกรมแก้ไข ตารางคำนวณของเครื่อง Server จะอัปเดตยอดสะสมและประมวลผลอัตโนมัติทุกคืน และสามารถเข้ามาเปิดเช็กผลการทำงานย้อนหลังได้จากไฟล์ `/opt/Customer-Project/backend/cron_update.log`

> [!IMPORTANT]
> ต้องให้การนำเข้าข้อมูลดิบทั้งสามตารางเสร็จสมบูรณ์ก่อนเริ่ม `update_data.js` และควรเลือกใช้ตัวตั้งเวลาเพียงทางเดียวระหว่าง host crontab กับ built-in node-cron แม้ตัวสคริปต์จะมี MySQL named lock ป้องกันการคำนวณซ้อนกันแล้วก็ตาม ระหว่างทำงานสคริปต์จะตรวจ generated columns/indexes และรัน `ANALYZE TABLE proj_cus, debt_trn` ก่อนคำนวณรายงาน

## ⚙️ การตั้งค่าสภาพแวดล้อมระบบและการแก้ไขไฟล์ .env บน Server (Environment Configurations)

เนื่องจากระบบงานบน Linux Server ไฟล์ชื่อ `.env` ที่เก็บค่าตัวแปรเชื่อมฐานข้อมูลและพอร์ตระบบ จะเป็นไฟล์ซ่อน (Hidden File) ตามมาตรฐานของระบบปฏิบัติการ หากคุณหาไฟล์ไม่เจอ ให้ดำเนินการดังนี้:

### 1. การดูรายการไฟล์ทั้งหมดรวมไฟล์ซ่อน
ให้ระบุอาร์กิวเมนต์ `-la` เพิ่มเติมเมื่อใช้คำสั่ง `ls`:
```bash
cd /opt/Customer-Project/backend
ls -la
```
คุณจะพบไฟล์ชื่อ `.env` แสดงในผลลัพธ์

### 2. วิธีการแก้ไขค่า `.env` บนเซิร์ฟเวอร์
สามารถเลือกใช้โปรแกรมแก้ไขข้อความใน Terminal เช่น `nano` เพื่อปรับเปลี่ยนรหัสผ่าน ค่าฐานข้อมูล หรือพอร์ตได้โดยตรง:
```bash
nano .env
```
*เมื่อปรับปรุงเสร็จแล้ว:*
*   **บันทึกไฟล์**: กดปุ่ม `Ctrl + O` แล้วกด `Enter`
*   **ออกจากโปรแกรม**: กดปุ่ม `Ctrl + X`

### 3. ตัวอย่างการกำหนดค่าภายในไฟล์ `.env`
```env
PORT=5000
DB_HOST=127.0.0.1
DB_PORT=3306
DB_USER=root

DB_DATABASE=pcis
```
*(หมายเหตุ: หากปรับแก้ค่าตัวแปรใน `.env` บน Docker Server อย่าลืมสั่งรีสตาร์ทบริการหลังบ้านเพื่อให้ค่านำมาใช้งานใหม่)*
